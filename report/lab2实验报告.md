## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

Lab2 围绕物理内存的发现、初始化和分配展开。内核先在 entry.S 中建立启动映射并准备栈，进入 kern_init() 后清零 BSS，再通过 dtb_init() 解析设备树，得到物理内存起点和大小。随后 pmm_init() 选择管理器，由 page_init() 建立 Page 描述符并排除固件、内核和描述符数组占用的页面，将可用完整页交给管理器。

在此基础上，实验先分析已有的 First-Fit，再实现 Best-Fit 和 Buddy，并通过统一的 pmm_manager 接口接入内核。First-Fit 选择首个够大的空闲块，Best-Fit 选择满足请求的最小块，Buddy 按二次幂大小组织块并通过拆分和伙伴合并完成分配与回收。不同算法处理的是同一类物理页资源，调用者统一使用 alloc_pages()/free_pages()。

页表负责虚拟地址到物理地址的映射，Page 描述符记录物理页的管理状态，分配器负责物理页的分配和回收。实验通过内存信息获取、描述符初始化、分配策略实现与测试验证，建立物理内存管理的完整流程。

### 2.2 功能的逐步实现

1. 首先理解启动代码、Sv39 映射和设备树解析，获得内核可访问的物理内存范围。这些信息是后续建立描述符和确定空闲区的前提。
2. 接着完成 page_init()，设置地址转换所需信息、建立 pages 数组，排除固件、内核及描述符等占用区域，将剩余完整页面交给当前管理器。
3. 在统一的 pmm_manager 接口下阅读 First-Fit，理解链表、块首 property、分配拆分和释放合并，再实现并接入 Best-Fit，比较首个适配与最小适配的区别。
4. 进一步实现 Buddy System，以各阶链表组织二次幂块，完成请求取整、逐级拆分和真正伙伴合并，并通过 PMM_USE_BUDDY 在构建时选择管理器。
5. 最后执行分配器自检和针对性测试，检查初始化、分配、释放、边界行为及状态恢复；结合页表与 TLB 调试理解访存地址转换和物理页管理之间的关系。

**功能说明：**

新增 code/kern/mm/buddy_pmm.c 和 buddy_pmm.h，在 pmm.c 中增加选择逻辑。定义 PMM_USE_BUDDY 时选择 buddy_pmm_manager，否则保持 Best-Fit；不修改 Page 结构、公开分配接口、page_init()、First-Fit、Best-Fit 或评分工具。

- **初始化与登记：** buddy_init() 清空各阶链表和计数。buddy_init_memmap() 接收连续 Reserved 页面，检查后逐段选择不超过剩余长度、且起点按物理页号对齐的最大二次幂块，保证非二次幂长度和非大块对齐起点也不丢页。
- **分配与拆分：** n 页请求向上取整到最小的 2^k 页，从对应阶向上查找空闲块。需要拆分时保留低地址半块，将高地址半块放回对应阶链表。没有合适块或请求无法安全取整时返回 NULL，失败不改变原状态。
- **记录与计数：** 私有标志区分管理页、已分配页和分配块首。空闲块首的 property 记录实际块页数；已分配块首的 property 记录原始请求 n，实际大小可由 n 重新取整计算。nr_free 按实际占用页数增减，不依赖堆分配器保存记录。
- **释放与合并：** 调用者传入原首页和原始 n。先检查范围、块首、请求大小和整块页面状态，再回收整个实际块。伙伴首页物理页号按 page2ppn(base) ^ (1 << order) 计算，仅同阶、空闲且状态合法的真正伙伴可合并；相邻但非伙伴不能合并。合并选择低地址首页并升阶继续，不重复增加 nr_free。
- **测试接入：** buddy_check() 注册到管理器的 check 成员，由启动流程实际调用。受控布局使用独立测试描述符，保存并恢复真实状态后，再用合法地址转换进行真实物理页数据隔离测试。

### 功能模块：模块二任务二——Best-Fit连续物理内存分配算法

**负责人：** 2413625-张龙飞

#### 模块功能描述

**功能说明：**

**空闲块组织。** 使用 free_area 中的循环双向链表和 nr_free 管理空闲区。链表按物理地址递增排列，每个空闲块仅将首页面的 page_link 接入链表；块首设置 PageProperty，property 记录连续页数，nr_free 记录空闲页总数。Page 描述符保存管理信息，不是实际数据页，也不是硬件页表项。

**best_fit_init() 与 best_fit_init_memmap()。** 前者初始化链表并将计数清零。后者接收 page_init() 交付的连续 Reserved 页面，先检查整个范围的状态，再清除保留标志、重置 property 和引用计数，最后登记为空闲块。这里重置的是描述符元数据，不是把对应物理页中的数据全部清零。

**best_fit_alloc_pages()。** 申请 n 页时，先检查 n>0；总空闲页不足时直接返回 NULL。随后遍历空闲块，选择长度不小于 n 的最小块。因为链表按地址排序，且只在发现严格更小的候选块时替换，所以长度相同时保留地址较低者；遇到恰好 n 页的块即可提前结束。核心选择条件为：

```c
if (p->property >= n &&
    (page == NULL || p->property < page->property)) {
    page = p;
    if (p->property == n) {
        break;
    }
}
```

选中后从链表删除原块首，清除其空闲块首状态，从低地址端交付恰好 n 页。若原块更大，则用 page+n 作为剩余块首，设置剩余长度并放回原链表位置，保持地址顺序。最后 nr_free 只减去 n。若总空闲页足够但没有足够大的连续块，也返回 NULL，不拼接不相邻页面，失败不改变状态。

**best_fit_free_pages() 与 best_fit_insert_block()。** 释放接口检查待回收页面不是 Reserved 或已有空闲块首，重置元数据，再调用辅助函数插入。辅助函数先按地址确定位置，并检查新范围与前后空闲块不重叠；登记新块后只增加一次 nr_free，再依次尝试合并前块和后块。合并前块后要把 base 更新为合并后的块首，才能正确继续检查后块；失效块首的标志、长度和链表连接也要清除。合并只改变块边界，不再次增加空闲页数。

本实现允许释放原分配范围内的合法连续子区间，不要求申请与释放一一按原始块大小对应。调用者仍须保证范围有效、已经分配且没有重复释放；现有断言不能代替完整的分配所有权记录。

**best_fit_nr_free_pages() 与管理器接入。** 计数接口只返回 nr_free，不修改状态。best_fit_pmm_manager 将上述函数及已有 best_fit_check() 注册到统一接口，使 alloc_pages()/free_pages() 转发到本算法。任务二完成时选择 Best-Fit；整体完成后可以用宏选择执行哪个算法。

#### 问题回答：Best-Fit 算法是否有进一步的改进空间？

当前实现采用按物理地址排序的双向链表管理空闲块，申请时选择足够大的最小块，精确分配 n 页；释放时按地址插入并合并相邻空闲块。设空闲块数为 F，申请最坏需要遍历全部空闲块，时间复杂度为 O(F)；释放 n 页还需检查和重置页面状态，复杂度为 O(n+F)。

还有改进空间。一是增加按块大小和地址组织的平衡树等索引，降低最小适配块的查找成本，但拆分、合并以及现有测试恢复状态时必须同步维护索引。二是在修改页面状态之前增加范围和所有权检查，更可靠地定位越界、重叠或重复释放。目前的相邻块合并可以减少部分外部碎片，但 Best-Fit 只使本次剩余空间尽量小，不保证长期碎片最少，也无法合并被已分配页面隔开的空闲块。

| 非二次幂请求 | 申请3页占4页、5页占8页，传原始请求释放 | 检查实际占用范围与计数变化，发现错误扣减、请求记录错误或取整尾页漏回收 |
| 逐级拆分 | 从16页块申请1页，检查剩余1、2、4、8页块，并继续分配剩余全部页面 | 确认所有尾块仍可使用，发现拆分丢块、重复分配或链表登记错误 |
| 伙伴合并 | 多级合并、不同释放顺序，以及相邻但不互为伙伴的块 | 释放真正伙伴后可重新申请大块；相邻非伙伴不能满足更高阶申请，发现误合并或漏合并 |
| 分配失败 | 空池、总量不足、无合适阶及超大请求 | 要求返回 NULL，失败前后状态指纹不变，发现失败路径修改计数或破坏已有分配 |
| 真实页数据隔离 | 申请1、3、5页，对实际1、4、8页写入不同标记并逐字节复查 | 覆盖取整尾部，发现物理页重叠、越界覆盖及实际数据损坏 |
| 多轮操作与恢复 | 固定种子执行128步交错分配释放，逐步检查结构，结束后归还全部页面 | 核对计数、非重叠和块状态，并重新申请整个测试区，发现累积错误和资源泄漏 |

结构检查同时核对各阶链表与 Page 描述符：块大小应与阶数一致、起点按物理页号对齐、页面状态一致，链表与描述符统计的空闲页数均应等于 nr_free。仅比较空闲页总数不足以排除重叠块或错误归属。

### Challenge：SLUB 内存对象分配器

#### 测试设计

SLUB 测试由内核单核测试和宿主多线程测试两部分组成。二者共享同一份 code/kern/mm/slub.c 和 code/kern/mm/slub_test.c；宿主侧只通过 slub_port.h 替换 CPU 定位、锁和页分配实现，不为测试另写分配器。内核测试以 -DSLUB_TEST 构建，在 pmm_init() 和 slub_init() 完成后运行。由于测试结束后内核仍在 while(1) 中空转，运行脚本不以 QEMU 的退出码判定结果，而是轮询日志中的 SLUB_TEST_PASS、SLUB_TEST_FAIL 和 panic 标记，并设置超时，避免把挂起误判为通过。

测试首先区分对象的不同持有状态。对单个 slab 而言，slab.inuse 表示不在 slab 空闲链上的对象数，等于“用户持有对象数 + sheaf 缓存对象数 + barn 缓存对象数”；只有 inuse == 0 时，slab 才没有任何引用，可以转为空 slab。每个尺寸类最多保留 SLUB_EMPTY_KEEP（2）个空 slab，多余的空 slab 立即归还页面。slub_shrink() 在调用者静止的前提下排空所有 CPU 的 main/spare sheaf 和共享 barn，释放全部空 slab，但保留用户仍持有的对象（相关实现见 code/kern/mm/slub.c:563 和 code/kern/mm/slub.c:828）。因此，“用户对象计数归零”并不等于“页面可以归还”，cached_pages 用例专门检查这条页所有权边界。回收基线在 slub_shrink() 后记录；slub_fixed_overhead() 单独给出静态元数据开销，页泄漏检查严格比较空闲页数，不设置容差。

并发路径由 slub_port.h 抽象。sheaf 命中的分配只在本地临界区内完成，不获取全局锁；共享 barn、各尺寸类的 cache、全局 slab 归属索引和底层页分配器分别加锁，锁序为 local → barn → cache → index → pmm，barn 与 cache 不嵌套。本地临界区只防止同核中断重入，不承担多核互斥。需要注意的是，小对象 kfree() 为确认对象所属 slab，仍需获取全局索引锁，因此释放路径不是完全无锁的。

#### 补充验证

1. 逐操作内部检查。宿主 make -C tools/host debug 以 -DSLUB_DEBUG -DSLUB_TEST_VALIDATE 构建，在每次分配和释放后调用 slub_debug_validate()（code/kern/mm/slub.c:1047）。该检查验证 slab 空闲链无环、链长与 inuse 之和等于容量、partial/empty/full 链的状态一致，并用“Σ slab.inuse = 用户持有 + sheaf + barn”核对对象四态互斥。该校验按静止态设计，当前测试中只在宿主顺序 debug 构建里逐操作启用；并发测试没有定义 SLUB_DEBUG，因此调试模式下的并发安全性不在本轮已验证范围内。
2. 真实多线程。宿主 code/tools/host/slub_host_mt.c:297 使用 4 个工作线程并绑定不同逻辑 CPU，通过真实 pthread 互斥和固定页池模拟底层页分配。mt_ring 让线程组成环形生产者-消费者：一侧分配并写满对象，经同步队列交给另一侧校验并释放，共传递 24000 个对象；检查跨 CPU 交接后的内容、全局活跃地址唯一性、生产与消费计数相等，并设置 60 秒死锁超时。mt_churn 由各线程维护私有对象集，执行 4000 轮混合分配/释放，集中制造共享 barn、slab 和页分配器的竞争，周期性校验内容并在结束后检查回收基线。该测试验证的是宿主 Linux 用户态多线程，不是 RISC-V SMP；通过只说明已覆盖的交错未暴露问题。
3. 误用测试。code/tools/host/slub_host_neg.c:95 将四类误用分别放入 fork 子进程：小对象重复释放、大对象重复释放、释放非本分配器指针、释放非 16 字节对齐指针。父进程要求子进程异常终止并输出 panic 文本，预期 panic 不会中止正常测试集，从而验证重复释放和非法指针的诊断路径。

## 六、实验总结与收获

### 对操作系统的理解

1. 本实验涉及的主要知识点及其与 OS 原理的关系：

| 实验知识点             | 对应原理及关系                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 物理内存发现与初始化   | 设备树提供 RAM 范围，内核还要排除保留和已占用区域，硬件存在的内存不等于当前可以分配的内存                                    |
| Page描述符与物理页     | 描述符保存管理信息，实际数据仍在物理页中；数组下标、物理页号和数据地址具有不同含义                                           |
| 空闲链表与连续分配     | 使用循环双链表连接空闲块首页，property记录块大小；链表相邻不等于物理连续，释放时需检查块边界                                 |
| First-Fit与Best-Fit    | 分别选择首个够用块和最小够用块，体现连续分配中的不同搜索策略；最小剩余不保证长期碎片最少                                     |
| Buddy按阶分配与合并    | 用二次幂块组织连续页，通过对半拆分满足请求；合并要求同阶且互为伙伴，物理页号异或用于定位另一半                               |
| 内部与外部碎片         | Buddy申请3页占4页产生内部碎片；空闲区分散时，总空闲量足够也可能无法满足连续分配，合并有助于恢复大块                          |
| 统一管理器接口         | 调用者使用相同接口，由函数指针转发到具体算法，实现框架与分配策略的分离                                                       |
| Sv39与地址转换         | 单张页表4KiB、512项，每项8字节；通过页表映射虚拟页和物理页，页内偏移不变。启动根表可用叶子项建立大页映射，并非每次都走满三级 |
| 页表与物理页管理的区别 | 页表决定地址如何访问，分配器决定物理页归属；已经建立映射并不表示对应页面空闲                                                 |

2. OS原理中重要、但本实验尚未完整实现的内容包括：进程创建与调度、进程独立地址空间、按需分页与页面置换、交换空间，以及多核并发内存分配的同步机制。当前工作主要完成物理页管理和启动映射的理解，尚未建立完整的进程虚拟内存系统；选做的SLUB小对象分配已实现并接入页分配器，完成了单核功能测试与宿主测试，但尚未在真实多核内核环境中验证并发正确性。

### AI 协作开发的经验

小组协作中需要先明确各模块的职责和共同接口，再向AI提供真实代码及可信前提。提示词通过PROMPT、RELY、GUARANTEE和SPECIFICATION分别描述任务范围、已有条件、交付要求和具体行为，减少不同模块之间接口或状态约定不一致的问题。

测试要求应与功能规格对应。例如，物理内存初始化要检查占用区排除和页面对齐，分配器要检查块选择、拆分、回收及计数；Buddy还需区分原始请求与实际占用，并验证真正伙伴关系。将实现和测试分开组织，有助于根据生成后的真实数据结构补充边界用例。

AI生成结果仍需结合代码阅读和实际运行判断。编译成功只能说明语法和链接等基本环节通过，不能代替功能验证；测试应检查状态变化、失败路径和结束后的资源恢复。各成员保留所用提示词、实际问题和运行日志，合并时核对管理器选择、编译参数和测试条件，保证实现与报告中的结论一致。
