## 三、实验整体逻辑分析

### 3.1 本章节的逻辑主线

Lab4 在 Lab2 的物理页分配、基础页表和 Lab3 的 Trap 恢复之上，依次解决三个问题：如何维护页映射，如何创建可运行的线程，如何让 CPU 执行选中的线程。内核线程共享内核页表，各自拥有 PCB、栈和执行现场。

```text
OpenSBI → kern_entry（启动页表、启动栈）→ kern_init
  → pmm_init → pic_init / idt_init → vmm_init → proc_init
  → clock_init / intr_enable → cpu_idle → schedule → proc_run → switch_to
  → forkret → forkrets → __trapret → sret → kernel_thread_entry → init_main
```

`proc_init()` 创建 init 后，`current` 仍指向 idle。首次切换由 `cpu_idle()` 检查已置位的 `need_resched` 后主动发起，无需等待时钟中断。

### 3.2 功能的逐步实现

| 阶段         | 实现文件                                                                                      | 交给下一阶段的结果                                                                    |
| ------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 页映射维护   | [pmm.c](../code/kern/mm/pmm.c)                                                                 | 保持 PTE、物理页引用数和 TLB 一致                                                     |
| 内核线程创建 | [proc.c](../code/kern/process/proc.c)、[proc.h](../code/kern/process/proc.h)                    | 线程持有独立内核栈、可查找的 PID 和可恢复现场                                         |

### 功能模块：模块一——虚拟内存页操作功能

**负责人：** 2413357-王逸凌

**目标文件：** [kern/mm/pmm.c](../code/kern/mm/pmm.c)，标记 `LAB4 function1 2413357`。

#### 模块功能描述

- `page_insert(pgdir, page, la, perm)`：通过 `get_pte(pgdir, la, 1)` 定位槽位；失败返回 `-E_NO_MEM`。成功取得槽位后先增加新页引用。有旧映射时分两种情况：同页就抵消刚加的引用，异页就给旧页减一次，旧页引用归零才释放。最后覆盖 PTE、更新权限、失效该地址的 TLB，返回 0。
- `page_remove(pgdir, la)`：用 `get_pte(pgdir, la, 0)` 查找，不申请新页表页。槽位不存在或无效就返回；否则先清 PTE 并使旧翻译失效，再减引用，归零才释放数据页。

例如将 `p1` 映射到 A、`p2` 映射到 B，然后用 `p1` 替换 B：`p1` 的引用由 1 变 2，`p2` 的引用由 1 变 0。再次用 `p1` 更新 B 的权限时引用仍为 2，同时必须失效 B 的旧权限缓存。撤销 A 和 B 后引用依次降到 1 和 0。中间页表页不是被映射的数据页，`page_remove()` 不负责回收它们。若第二层页表分配失败，`get_pte()` 可能保留已挂接的空中间表；目标叶 PTE 与目标数据页引用未改动。

这里 `get_pte()` 返回的是可读写的页表槽地址，非空不代表槽内已有有效映射。代码用 `PTE_V` 判断是否存在旧映射，用 `pte2page()` 找到旧页描述符，以 `pte_create()` 从新页号和新权限重新构造 PTE。替换时不是在旧 PTE 上直接追加权限，因此旧的用户或写权限可以被清除。`get_pte(create=1)` 分配的是中间页表页；调用者要映射的数据页已经通过参数传入，与后续实验的缺页分配不同。

#### 实现迭代过程

[prompt_1.md](prompt_1.md) 将首映射、同页更新、异页替换、撤销和分配失败分别写成规格，并要求判断现有辅助函数是否可用。容易引入的缺陷是同页重映射时先把旧页唯一引用减到 0，导致页被提前释放；最终实现先取新引用，再在同页分支抵消。此风险由规格预先约束，没有记录显示它曾在生成代码中触发。集成测试验证了同页重映射没有改变引用数和空闲页数。

### 功能模块：模块二——进程创建及初始化功能

**负责人：** 2413625-张龙飞

**目标文件：** [kern/process/proc.c](../code/kern/process/proc.c)，标记 `LAB4 function2 2413625`。

#### 模块功能描述

| 核心函数            | 实现说明                                                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `alloc_proc()`    | 申请并清零 PCB；置 `PROC_UNINIT`、PID -1、内核页表物理基址，初始化两条链表的内嵌节点。                                                                                       |
| `proc_init()`     | 初始化进程链表和哈希桶。idle 使用 PID 0 和 `bootstack`，设置 `need_resched=1`，记入总数但不进普通双表。令 `current=idleproc` 后创建 PID 1 的 init，并按 PID 找回与命名。 |
| `kernel_thread()` | 在当前栈上清零临时 Trap frame，以 `s0/s1` 保存函数和参数，以 `epc` 指向 `kernel_thread_entry`，设置返回到 S 态所需状态，再调用 `do_fork`。                             |
| `do_fork()`       | 检查进程数上限，申请 PCB 和两页内核栈，记录父线程，调用 `copy_mm/copy_thread`。关本地中断分配 PID、挂入哈希和链表、递增总数；恢复中断后才唤醒，返回 PID。                    |
| `copy_thread()`   | 将 Trap frame 复制到新栈顶部，把子进程返回约定的 `a0` 设为 0；设置保存的 `sp`，让 `context.ra=forkret`、`context.sp` 指向新帧。                                        |
| `copy_mm()`       | 保留接口并返回 0，内核线程的 `mm` 继续为 `NULL`。作为切换依据的 `pgdir` 仍指向共享内核页表。                                                                             |

`do_fork()` 在可能失败的资源申请之后才登记和唤醒。达到上限返回 `-E_NO_FREE_PROC`；申请 PCB 失败返回 `-E_NO_MEM`；栈分配失败只释放 PCB；若 `copy_mm()` 返回错误，则先释放栈、再释放 PCB，并保留原错误码。当前 `copy_mm()` 总是成功，其清理分支属于代码审查范围。

`context` 用于函数调用边界的切换；Trap frame 用于恢复更完整的寄存器和特权状态。第一次恢复 `context` 时，普通 `ret` 到达 `forkret`；它经 `forkrets` 把新线程的 Trap frame 交给 `__trapret`。`sret` 按 `sepc` 进入 `kernel_thread_entry`，后者把 `s1` 放入第一参数寄存器 `a0`，再调用 `s0` 指向的函数。

创建 init 时，父 PCB 是 idle，但 idle 没有要复制的初始 Trap frame，因此 `kernel_thread()` 构造一个模板，`copy_thread()` 将它复制到新栈，不能在创建函数返回后继续引用模板。普通调度链表按节点顺序访问，PID 哈希表用于按编号查找；两个表使用 PCB 内不同的节点。线程完成栈和上下文初始化后才登记并唤醒，避免调度器看到一个尚不能恢复的就绪线程。

### 功能模块：模块三——进程调度

**负责人：** 2412303-袁煜杰

**目标文件：** [kern/process/proc.c](../code/kern/process/proc.c)、[kern/schedule/sched.c](../code/kern/schedule/sched.c)、[kern/process/switch.S](../code/kern/process/switch.S)，标记 `LAB4 function3 2412303`。

#### 模块功能描述

| 核心函数        | 实现说明                                                                                                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cpu_idle()`  | 在启动线程的空闲循环中检查 `need_resched`，有请求时调用调度器。                                                                                                           |
| `schedule()`  | 关本地中断、清当前请求。idle 从哨兵开始，普通线程从自己的下一个节点开始；跳过哨兵并环绕，找首个 `PROC_RUNNABLE`。找不到就回退 idle。选中时累计 `runs`，目标不同才切换。 |
| `proc_run()`  | 关本地中断，先更新 `current`，再把 Sv39 MODE 和目标根页表的物理页号写进 `satp`，刷新 TLB，然后调用 `switch_to`。原线程切回时从调用后继续并恢复自己的中断状态。        |
| `switch_to()` | 在 `from/to` 的 `struct context` 中按机器字偏移保存和恢复 `ra/sp/s0–s11`，最后执行 `ret`。每个线程自己的调用栈一直留在原地，不需要复制。                           |

先改 `current` 是因为新线程的 `forkret()` 会读取 `current->tf`。返回位置取决于线程是否运行过：新线程预置 `ra=forkret`，已运行线程的 `ra` 则是上一次 `switch_to()` 的调用返回点。仓库实现按链表顺序循环选择，新建线程从表头挂入；没有严格 FIFO 入队，也没有时间片抢占。

在本实验里，线程切换前后通常使用同一个内核页表；写入 `satp` 和刷新 TLB 仍然属于通用的切换步骤。调度器找不到就绪线程时退回 idle；如果环绕后又选中当前线程，会增加它的 `runs`，但不会调用 `proc_run()`。因此 `runs` 表示被选中的次数，不能当成实际切换次数或 CPU 时间。

[prompt_3.md](prompt_3.md) 分别为四个函数规定前置条件和结果，覆盖 idle 出发、普通节点环绕、无可运行项、不必切换及首次和再次恢复。规格要求按 `struct context` 的布局使用 `REGBYTES`，也明确避开遗留的 Sv32 `lsatp()`。最终实现显式写入 Sv39 `satp` 并调用 `flush_tlb()`。这些是实现约束和预防性处理；没有保留早期生成版本误用该接口的记录。

### Challenge：关中断与分页模式

**`local_intr_save(intr_flag)` 和 `local_intr_restore(intr_flag)` 如何工作？** 前者读取本 hart 的 `sstatus.SIE`，把原中断状态存进标记；原来开着才关闭。后者只在保存的标记表明原来开启时重开。若 `schedule()` 外层保存到 1，`proc_run()` 内层看到的就是 0，内层恢复不会意外开中断。这个办法不能排除其他 hart 的并发访问，也不会阻挡当前指令同步引发的异常。

**`get_pte()` 的两段为什么相似？** Sv39 将虚拟地址分为三个 9 位页表索引和 12 位页内偏移。走到 4 KiB 叶槽前，前两层都要取索引、检查有效位，并在允许时申请、清零、挂接下级页表。Sv32 用两层各 10 位的索引、4 字节 PTE，只下降一次；Sv48 用四层各 9 位的索引、8 字节 PTE，需要下降三次。它们使用相同的逐级查找思想，区别在层数、索引和表项大小。

**查找和分配是否应拆开？** 当前教学代码用 `create` 复用寻址逻辑，调用点简洁，但需要读懂参数才知道是否分配，还要理解部分分配失败的状态。若继续扩展，适合把遍历与分配机制封装起来，对外分别提供只读查找和确保叶槽存在的接口，并定义大页叶项、部分创建回滚的规则。本次未为思考题改写 `get_pte()`。

### 启动自检与结果边界

在当前 WSL + QEMU 10.2.1 + OpenSBI v1.8 环境下实测 `make -j` 编译零报错，`make qemu` 补充检查正常通过：`check_alloc_page()`、`check_pgdir()` 和 `check_boot_pgdir()` 成功，`kmalloc_init()`、`check_vma_struct()` 与 `check_vmm()` 通过，随后内核切入 `initproc` 并打印上述三行消息。普通启动没有注入评分用例，三项得分以 `make grade` 为准。

三项通过后，`init_main()` 返回，框架已有的 `do_exit()` 占位打印 `process exit!!.` 并进入内核调试监控。这发生在各项断言和 init 输出之后。评分未覆盖资源分配失败注入、触及进程上限、多 hart 或时间片抢占，这些不计入本次实测结论。

## 六、实验总结与收获

### 对操作系统的理解

| 本实验知识点              | 对应的 OS 原理                   | 联系和差异                                                                                                  |
| ------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| VMA、Sv39 PTE 和 TLB      | 地址空间、分层页表、缓存一致性   | VMA 描述合法区间，PTE 决定具体翻译和页权限，TLB 加速查找；本实验用显式映射，不处理缺页分配。                |
| 页引用计数                | 内存共享及资源回收               | 一个物理页可以被多个虚拟地址指向，最后一个引用撤销之后才能释放；本实验没有实现写时复制。                    |
| PCB、独立内核栈、两类现场 | 进程与线程抽象、任务上下文、Trap | 线程共用地址空间却可独立执行；`context` 在受控调用边界切换，Trap frame 用于恢复被打断或预构造的运行状态。 |
| 就绪选择和主动调度        | 多道程序、CPU 共享               | 单 hart 轮流运行多个执行流，证明了并发路径；没有真正的多核并行或时间片抢占。                                |
| 本地中断保存与恢复        | 原子更新、并发控制               | 本地中断不会看到登记或切换的中间状态；其他 hart 仍需锁等额外同步。                                          |

本实验未实现用户进程的装载与隔离、系统调用式创建、完整的 `exit/wait` 回收、按需分页、页面置换、时间片与优先级调度。多核就绪队列、负载均衡和跨 hart 的 TLB 一致性也不在当前单 hart 实验范围内。

这几个边界解释了 Lab4 与后续实验的衔接：缺页处理需要用 VMA 判断访问是否合法，再决定是否分配页；用户进程需要建立自己的地址空间并处理特权级转换；完整退出必须在旧线程不再使用其栈后回收资源。当前实验分别准备了页表接口、线程对象与切换路径，但还没有实现相应的策略和回收动作。

### AI 协作开发的经验

提示词中最有用的是可逐项验证的条件。模块一用引用数的前后变化限定重映射；模块二用资源获取顺序限定失败清理，用真实汇编入口限定寄存器字段；模块三将空队列、重复选中当前线程、首次恢复和再次恢复分开。生成后先对照源码检查结构布局与现有接口，再用编译和串口结果确认行为。预先规避的问题、实际审查修订与运行中观察到的现象分别记录，避免把代码审查结论当成运行证据。
